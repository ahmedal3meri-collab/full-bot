## 0. فحص المجلد الحالي وقرار الموضع

هذا المشروع يُبنى داخل مستودع `full-bot`، الذي يحتوي فعليًا على **بوت تلغرام مستقل وشغّال** (`bot.py`, `handlers/`, `database.py`, `locales/`) في جذر المستودع. هذا البوت **لا علاقة له** بمنصة UAE Services Hub ولم يتم حذف أو تعديل أي ملف منه.

**القرار الموثّق:** بناء UAE Services Hub بالكامل داخل مجلد فرعي مستقل `uae-services-hub/` بجذر Node/Next.js خاص به (package.json, docker-compose, .env منفصلة). السبب:
- خلط تطبيق Python (بوت) مع تطبيق Next.js في نفس الجذر يسبب تضاربًا في أدوات البناء، الحزم، وملفات البيئة.
- كل مشروع يبقى قابلاً للنشر والصيانة بشكل مستقل بالكامل.
- لا حذف ولا تعديل لأي كود قائم — القاعدة الأساسية المطلوبة.

## 1. القرار الهندسي: البنية (موثّق)

**القرار: Next.js 15 (App Router) موحّد — Frontend + API/Server Actions — بدون NestJS منفصل.**

| المعيار | Next.js موحّد | NestJS منفصل |
|---|---|---|
| SEO (صفحة لكل إمارة/قسم) | ممتاز، SSR أصلي | يحتاج طبقة إضافية |
| سرعة التسليم لفريق صغير | عالية | أبطأ |
| Type-safety من DB للواجهة | Prisma + Zod مشتركة | تكرار DTOs |
| المهام الثقيلة (embeddings، إشعارات) | تُعزل في **Worker** منفصل (BullMQ) | نفس الشيء |
| الدردشة الفورية | **realtime** منفصل (Socket.IO) | نفس الشيء |

أربع خدمات تطبيقية:
- `web` — Next.js (UI + REST تحت `/api/v1` + Server Actions)
- `worker` — BullMQ (إشعارات، انتهاء الإعلانات، فهرسة RAG)
- `realtime` — Socket.IO (المحادثات)
- قاعدة البيانات/التخزين: PostgreSQL + Redis + Qdrant + MinIO

الكود منظّم modular داخل `app/` و`lib/modules/*`.

## 3. مبدأ مضاد للهلوسة في المساعد الذكي (للمرحلة 5 لاحقًا)

1. المساعد لا يملك إلا **أدوات** (`search_listings`, `search_providers`, `get_price_range`, `search_kb`).
2. صفر نتائج → «ما لقيت شي مطابق في المنصة» + اقتراح توسيع البحث. ممنوع الاختراع.
3. أي إجابة قانونية تُرجع مع **المصدر + تاريخ آخر مراجعة**. بدون مصدر → لا إجابة.
4. تحقق بعد التوليد: كل رقم درهم/اسم شركة يجب أن يطابق ID من نتائج الأدوات.
